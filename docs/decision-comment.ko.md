# 결정 요청 댓글

구현 중에 오너의 판단이 필요한 질문을 이슈나 PR의 댓글 하나로 남기는 서식이다. 규칙은 [TRACK-05](rules.ko.md)다. 대시보드는 `상태`가 `대기`인 댓글을 열린 질문으로 모은다. [English](decision-comment.md)

## 서식

```markdown
### 결정 요청: <한 줄 질문>

- 상태: 대기
- 막힘: 예

**배경**: <왜 이 질문이 생겼는가. 확인한 파일이나 동작>

**선택지**
1. <선택지> — <결과와 비용>
2. <선택지> — <결과와 비용>

**권장**: <번호> — <이유>

**결정**: 
```

## 쓰는 법

- 댓글 하나에 질문 하나를 쓴다. 첫 줄은 반드시 `### 결정 요청:`으로 시작한다.
- `상태`는 `대기`, `결정됨`, `철회` 중 하나다. `막힘`은 이 결정 없이 진행할 수 없으면 `예`, 권장안으로 먼저 진행 중이면 `아니오`다.
- 무엇을 만들지와 범위에 관한 질문은 이슈에, 구현 방법에 관한 질문은 PR에 남긴다. PR이 아직 없으면 이슈에 남긴다.
- 답을 받으면 새 댓글을 달지 않고 **같은 댓글을 고쳐** `상태`를 `결정됨`으로 바꾸고 `결정`에 선택과 날짜를 적는다. 오너가 답글로 답했다면 그 내용을 원래 댓글에 옮겨 적는다.
- 대화 중에 바로 답을 받은 질문도 `결정됨` 상태로 남긴다. 나중에 왜 그렇게 했는지 찾을 수 있어야 한다.
- 다시 볼 조건이 있거나 여러 작업에 걸치는 결정은 프로젝트의 결정 기록 문서에도 옮긴다.

## 에이전트 지침에 넣을 문구

```text
구현 중 오너의 판단이 필요한 질문은 .github/flow-atlas/docs/decision-comment.ko.md 서식으로
해당 이슈나 PR에 댓글로 남긴다. 대화에서 바로 답을 받았어도 결정됨 상태로 남긴다.
막힘이 아니오인 질문은 권장안으로 진행하고, 답이 다르면 되돌린다.
작업을 시작할 때 해당 이슈와 PR의 대기 상태 댓글에 답이 달렸는지 먼저 확인한다.
```
